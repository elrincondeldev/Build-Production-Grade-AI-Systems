# Glossary

Short, plain-language definitions. The number in brackets is the lesson where the term is taught in depth.

- **A/B test**: Sending different users to different versions and comparing an outcome metric with statistics. [4.6]
- **Adapter (code)**: A module that wraps an external system (LLM, DB, model file) behind your own interface so it can be swapped. [1.4]
- **Adapter (PEFT)**: Small trainable layers added to a frozen model to fine-tune it cheaply. [2.7]
- **Agent**: An LLM that decides which tools to call and in what order, in a loop, to reach a goal. [6.6]
- **Arithmetic intensity**: FLOPs performed per byte moved from memory; decides whether work is compute-bound or memory-bound. [3.2]
- **Artifact**: A versioned, immutable output of a pipeline (model file, index, dataset snapshot) plus its metadata. [1.5]
- **Audit log**: An append-only record of who did what and when; tamper-evident if hash-chained. [5.5]
- **Backoff (exponential, with jitter)**: Waiting longer after each failed retry, with randomness so clients don't retry in sync. [1.3]
- **Batch inference**: Scoring many records on a schedule (e.g. nightly) instead of per request. [1.2]
- **BM25**: A classic keyword-ranking function; strong for exact terms, IDs and rare words. [2.5]
- **Blue-green deployment**: Running two full environments and switching traffic from old (blue) to new (green) at once. [6.4]
- **Brier score**: Mean squared error between predicted probabilities and outcomes; lower is better. [4.2]
- **Burn rate**: How fast you are spending your error budget relative to plan. [6.4]
- **Calibration**: Whether predicted probabilities match observed frequencies (a 0.8 score should be right 80% of the time). [4.2]
- **Canary release**: Sending a small slice of traffic to a new version and promoting it only if metrics stay healthy. [4.6, 6.4]
- **Cascade**: Trying a cheap model first and escalating to a stronger one only when needed. [3.3]
- **Chunking**: Splitting documents into retrievable pieces. [2.4]
- **Circuit breaker**: Stops calling a failing dependency for a while so it can recover. [1.3]
- **Concept drift**: The relationship between inputs and the label changes, P(y|X). [4.5]
- **Context window**: The maximum number of tokens a model can read at once (prompt + output). [0.5]
- **Continuous batching**: Adding and removing requests from the running GPU batch at every decode step. [3.5]
- **Continuous training (CT)**: Automatically retraining models on new data on a schedule or trigger. [4.6]
- **Cross-encoder / reranker**: A model that scores a (query, document) pair jointly; slower but more accurate than embeddings. [2.5]
- **Data contract / schema**: A formal description of the shape and rules data must follow. [2.1]
- **Data drift (covariate shift)**: The input distribution changes, P(X). [4.5]
- **Data lineage**: The record of where data came from and what transformed it. [2.2]
- **Datasheet (for datasets)**: Structured documentation of a dataset's origin, composition and intended use. [5.6]
- **Decode**: The phase of LLM inference that generates output tokens one at a time; usually memory-bound. [3.2]
- **Distillation**: Training a small "student" model to imitate a large "teacher". [3.6]
- **Embedding**: A vector representing the meaning of text (or other data), so similar things are close together. [0.5]
- **Error budget**: The amount of unreliability an SLO allows (e.g. 0.1% of requests may fail per month). [6.4]
- **ETL / ELT**: Extract-Transform-Load vs Extract-Load-Transform (transform inside the warehouse). [2.1]
- **Eval gate**: A CI step that blocks a release if quality metrics regress. [4.3]
- **Experiment tracking**: Logging parameters, metrics, code version and artifacts of every training run. [2.6]
- **Feature store**: A system that serves the same feature values for training and online inference. [1.2]
- **Fine-tuning**: Further training a pre-trained model on your data. [2.7]
- **FlashAttention**: An attention algorithm that avoids writing the large attention matrix to GPU memory. [3.7]
- **Graceful degradation**: Serving a reduced but safe answer when a dependency fails. [1.3]
- **GraphRAG**: Retrieval that uses a knowledge graph of entities and relationships, not only chunks. [2.5]
- **Groundedness / faithfulness**: Whether an answer is supported by the retrieved context. [4.3, 5.5]
- **gRPC**: A binary RPC protocol over HTTP/2 with strict contracts (protobuf); fast service-to-service. [1.3]
- **Guardrail**: A check on inputs or outputs of a model (injection filters, PII redaction, policy rules). [5.5]
- **Hallucination**: A fluent but unsupported or false model output. [0.5]
- **Health vs readiness**: *Liveness* = the process is alive; *readiness* = it can serve traffic right now. [1.4]
- **HITL (human in the loop)**: Requiring human approval for some decisions or actions. [6.6]
- **HNSW**: A graph-based approximate nearest-neighbour index used by most vector DBs. [2.5]
- **HPA**: Kubernetes Horizontal Pod Autoscaler; adds or removes replicas based on metrics. [6.3]
- **Idempotency**: Doing the same operation twice has the same effect as doing it once; required for safe retries. [0.3, 1.3]
- **Indirect prompt injection**: Malicious instructions hidden in content the model reads (docs, web pages, emails). [5.2]
- **Isotonic regression**: A flexible, monotonic calibration method; needs more data than Platt scaling. [4.2]
- **JWT**: JSON Web Token; a signed token carrying claims such as user ID and role. [5.3]
- **KV cache**: Stored attention keys/values of previous tokens so decoding doesn't recompute them. [3.2]
- **Leakage**: Training on information that won't be available at prediction time; inflates offline metrics. [2.2]
- **LLM-as-judge**: Using an LLM to grade outputs; must itself be validated against human labels. [4.3]
- **LoRA**: Low-Rank Adaptation; fine-tunes small low-rank matrices instead of all weights. [2.7]
- **Memory-bound vs compute-bound**: Limited by moving data vs by doing arithmetic. [3.2]
- **Mixed precision**: Using 16-bit floats (FP16/BF16) for most operations to save memory and time. [3.6]
- **Model card**: Documentation of a model's intended use, performance, limits and ethical considerations. [5.6]
- **Model registry**: A catalogue of model versions with stages/aliases (e.g. staging, production). [2.6]
- **MRR**: Mean Reciprocal Rank; how high the first relevant result appears, on average. [2.5]
- **Observability**: Being able to answer new questions about a system from its outputs (logs, metrics, traces). [4.4]
- **ONNX**: An open model format that many fast runtimes can execute. [3.7]
- **OpenTelemetry (OTel)**: The vendor-neutral standard for traces, metrics and logs. [4.4]
- **p50 / p95 / p99**: Latency percentiles; p95 = 95% of requests are faster than this. [3.4]
- **PEFT**: Parameter-Efficient Fine-Tuning (LoRA, adapters, prefix tuning…). [2.7]
- **PII**: Personally Identifiable Information (names, emails, phone numbers, card numbers…). [5.4]
- **Platt scaling**: Calibration by fitting a logistic regression on model scores. [4.2]
- **PR-AUC**: Area under the precision-recall curve; the right summary for rare positives like fraud. [4.1]
- **Prefill**: The phase of LLM inference that processes the whole prompt in parallel; usually compute-bound. [3.2]
- **Prompt injection**: Input that makes a model ignore its instructions. [5.2]
- **Prompt registry**: Versioned storage of prompts with review, release and rollback. [4.6, 5.7]
- **PSI**: Population Stability Index; a common score for how much a distribution shifted. [4.5]
- **Quantization**: Storing weights/activations with fewer bits (INT8, INT4) to cut memory and latency. [3.6]
- **RAG**: Retrieval-Augmented Generation; fetch relevant documents and give them to the model as context. [0.5, 2.5]
- **RBAC**: Role-Based Access Control. [5.3]
- **Readiness probe**: Kubernetes check that decides whether a pod receives traffic. [1.5]
- **Recall@k**: Share of queries whose relevant document appears in the top k results. [2.5]
- **Red-teaming**: Deliberately attacking your own system to find failures. [4.3, 5.2]
- **Reproducibility**: Being able to rebuild the same model from commit + data digest + environment lock. [2.6]
- **Retry budget**: A cap on the share of requests that may be retries, to avoid retry storms. [1.3]
- **ROC-AUC**: Area under the ROC curve; can look great on imbalanced data even when precision is poor. [4.1]
- **RRF**: Reciprocal Rank Fusion; merges ranked lists from different retrievers. [2.5]
- **Semantic cache**: Reusing a previous answer when a new query is similar enough in embedding space. [3.5]
- **Shadow deployment**: Running a new version on real traffic without using its outputs, to compare safely. [4.6]
- **SLI / SLO / SLA**: Indicator (what you measure), Objective (internal target), Agreement (contract with penalties). [6.4]
- **Speculative decoding**: A small draft model proposes tokens that the large model verifies in one pass. [3.7]
- **Structured logging**: Logs as key-value JSON events instead of free text, so they can be queried. [1.4]
- **Structured output**: Forcing model output to match a schema (e.g. JSON validated by Pydantic). [5.5]
- **Throughput**: Work done per unit of time (requests/s, tokens/s). [3.4]
- **Token**: The unit a model reads and writes; roughly ¾ of an English word. [0.5]
- **Training/serving skew**: Differences between how features are computed in training and in production. [1.1, 2.2]
- **TTFT**: Time To First Token; what users perceive as responsiveness in streaming. [3.4]
- **Vector database**: A store optimised for nearest-neighbour search over embeddings, with metadata filters. [2.5]
